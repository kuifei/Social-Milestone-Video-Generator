# Phase 0 findings

**English** · [中文](phase0-findings.zh-CN.md)

These findings are retained as design evidence without API keys, private media URLs, or user assets.

- The original H3 experiment used the profile screenshot first and character turnaround second. Current H3 Max instead takes the screenshot as image_url and the character sheet as its single reference.
- MiniMax H3 reference-to-video produced usable 15-second, 9:16 clips at 768P with native audio.
- Character consistency improved materially when a turnaround sheet was supplied. The production pipeline therefore creates one by default.
- The dominant failures were semantic rather than container-level: page drift, corrupted profile text, duplicate characters, incorrect pointing, and failed candle actions.
- Exact closing copy should be rendered in post rather than generated by the video model.
- Model prompts must distinguish the right-hand Followers statistic from the left-hand Following statistic.
- Provider prompt syntax is not portable. H3 uses ordered image references; other providers may use different tokens, so prompt rendering belongs to the provider.
- A 2K request was not accepted as the default because the delivery is 1080×1920 and the higher tier had not demonstrated enough quality gain to justify its larger cost.
- Queue failures must retain request IDs and categorized errors; otherwise interruption recovery can accidentally create duplicate paid requests.

The next quality experiment is compositing an extracted character layer over the untouched screenshot. It is not part of the main pipeline until benchmarked on edge quality, shadows, occlusion, motion realism, latency, and cost.
